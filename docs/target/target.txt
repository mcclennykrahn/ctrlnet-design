1.1 课题背景（Project background）
    随着科技发展和时代进步，现代测绘也逐步进入信息化阶段，与传统测绘相
比,信息化测绘大幅度的提高了测绘工作的效率，缩短了工程的时间，并且从长
期的测量工作来看还节约了工程所需要的成本。传统测绘工作存在的仪器设备笨
重､作业强度大､工作周期长､效率低下等问题，在信息化测绘中都得到了很好的
解决，另外数据的获取方式更加智能化，满足不同测绘目的的需求，测量成果的
可靠性也有了进一步的保障，减少了在传统测量中时常遇到的由于测量成果超限
而不得不进行的返测或是补测工作[1]｡
    控制测量作为测绘工作的重要内容，直接决定了测量成果的精度｡而测量的
方案更是直接影响着测量工作开展的合理性和高效性，合理的测量方案可以使整
个工程的外业工作事半功倍。然而，目前控制网设计流程还较为复杂｡实际的工
程建设中常用的控制网设计方法是人工量算[2]。人工量算是指在已有的测区的纸
质地图上人工量算距离和角度并且设置测区临时采用的坐标系，以此获取地图上
控制点的坐标,获取控制网精度估算需要用到的值，从而实现控制网精度估算｡该
方法不仅受地形图购买成本限制,计算还过程十分耗时，需要人为的列立误差方
程并通过系数矩阵计算控制网的精度，而且一旦估算的的控制网精度不满足要求
就需要重新布网开始计算，又给测绘人员添加了不必要的工作量[3]。
    此外,实际生产中的测绘要考虑到城市建设的各种因素,最重要的就是获取地
表和人文情况，而这一切问题的解决离不开基础测量数据｡但是在现如今这个城
市突飞猛进的时代,地理信息数据成指数型增长,数据信息更新十分频繁。若还想
采用原有的传统测绘技术通过全站仪一类的仪器进行实地的测量，毫无疑问在人
力和物力上都是很大程度上的浪费，必须承认常规的野外作业采集数据的方法已
很难适应当今社会的高速发展带来的海量地理信息的需求,更无法满足工程测量
的便捷性和灵活性，若想实现测绘工作的高效便捷必须着眼于当今高速发展互联
网[4]｡
    综上,结合多方面因素考虑结合在线地图实现设计，如今在线地图已被开发
投入生产很长有一段时间，在各方面性能完备的同时具有很多优越之处，利用在
线地图丰富的 API 功能,开发适用于控制网设计系统的网页端应用,从而提高内业
设计工作､外业测量准备工作的效率,为实现控制网布设与精度估算工作一体化
提供了新途径[5]。另外在线地图的时效性还能够满足城市内地理信息频繁的问题，
结合以上因素考虑实现具有控制网设计功能模块、控制网精度估算功能模块的网

2.1 主流在线地图介绍（Mainstream online map introduction）
2.1.1 主要地图服务商
   谷歌地图隶属于美国谷歌公司｡谷歌地图的前身是一家从事数字地图测绘的
公司，目前所提供的地图主要由卫星图、地形图以及基础矢量地图组成。谷歌地
图具有分辨率高、全球覆盖范围大的优点。谷歌地图于 2005 年 6 月开始从原有
的美国、英国和加拿大，扩大至全球，并于 9 月出版大陆版本。谷歌地图最先开
创了“街景视图”服务，供用户看到街道和社区的视角查看街景，然而这一功能
也因为侵犯个人隐私而备受争议[10]。2015 年 7 月，谷歌地图因移除黄岩岛中文
标注而引起热议并最终退出中国市场，目前谷歌地图开发的应用在国内使用会受
到网络访问限制，必须更换网络节点才能正常使用，并且不时会出现应用崩溃的
现象，种种不稳定因素也导致目前在国内谷歌地图的受用群众并不高。
   高德地图隶属于阿里巴巴公司。高德地图在导航､定位以及电子地图等多个
服务方面有着优秀的表现，另外高德地图在 iOS 端的开发十分完善，在与苹果公
司合作的多年时间里，也让高德地图拥有在手机端最多的月活跃用户[11]。但同时
高德地图也存在着系统兼容性略差、地图的更新速度慢、部分地区定位精度误差
大的缺点｡
   百度地图是由百度公司自主研发的在线地图应用，使用的地图数据由四维图
新提供。多年来，百度公司大力发展百度地图业务，凭借其在国内互联网上强大
的影响力，百度地图在众多功能都实现了许多重大突破，与国内众多企业都有业
务上的合作，而这在另一方面也极大程度上的完善了百度地图在原有的各方面不
足，百度地图在人工智能方面的多年奋斗也让其在这一方面处于全世界领先的水
平。据统计显示，目前有越来越多与在线地图相关的应用程序是基于百度地图实
现的[12]。

3 控制网精度估算原理
3 Principle of accuracy estimation of control network
3.1 控制网绘制（Control network drawing）
   控制网设立二等、三等、四等、一级和二级五个标准，程序中添加下拉菜单
来选择不同的等级以此来传出限差。控制网的布设采用手动构网，由于百度地图
JavaScript API GL 和 JavaScript API v3.0 只提供二维的平面坐标，因此只考虑平
面控制网的构网。而没有了高度的涉及就不能考虑到两点之间的通视问题，也就
会导致由算法自动构成的网在实际的测量中不能投入使用。因此选择手动构网排
除两点之间不能通视的问题，确保生成的网形在实际的测量工作中能够投入使用。
   在地图中通过鼠标左键来拖拽地图，通过右键可以生成标记点，滚动鼠标滑
轮可以放大缩小地图，另外地图左上角添加了地图控件用于精确选点。地图中会
按照点击顺序在标记点上添加点号，并自动在点库中生成该点的信息并保存用于
后续操作，若想删除某个点的信息并在地图中删除该点标记，点击在点库中该点
信息最后的删除按钮即可实现，若删除的点号是目前网中点号最大的，那么在删
除该后继续创建的点号将从删除的点号依次增加，若删除的点号不是网中最大的，
那么在删除该点后，点号比该点大的所有点的编号都会自动减一，并且表中的信
息也会自动改变。

3.3 控制网精度估算（Control network accuracy estimation）
   整个设计不考虑高程，只对平面网进行分析。平面网是指用经典的测量手段
(测边，测角等)布设的平面控制网，根据观测值的类型及网的几何图形变化，平
面网分为三角网、三角锁、三边网，导线网等不同网型｡[19]平面网的精度估算的
目的主要是结合整个网中所有的控制点，以及它们直接构成的方向值、边长、方
位角进行整个网的精度估算来初步确定网的质量[20]。
1. 平面网的观测值
   平面网的观测值为方向值，边长和方位角三类。对于一个具体的平面网,三
类观测值不一定全部存在。例如，传统的三角网仅有方向值，导线网既有边长又
有方向值，三边网仅有边长观测值 [21]。方向值是用经纬仪或全站仪测得的观测
值,它是测站点至照准点的观测方向线在测站水平面上的投影线与仪器度盘零线


                                  10
                      3 控制网精度估算原理



之间的夹角。方向值的误差方程式涉及到两个点的坐标值，其中包括一个测站点
和一个照准点，因此需要四个坐标值。两方向的方向值之差为角,实用中也可以
用角度值取代方向值用于平面网的平差,角度的误差方程式涉及到三个点的坐标
值，其中包括一个测站点和两个照准点，因此需要用到六个坐标值。边长观测值
是用电磁波测距仪或全站仪测得的距离观测值，它通常是测站点测距仪的仪器中
心到照准点的棱镜中心之间的直线距离，通常称为斜距，平差前也应将斜距归算
为高斯投影平面上的平面距离 [22]。但由于整个设计不考虑高程值，所以直接在
地图上得到对两点之间的实际距离不需加以改正，变边长的误差方程式涉及到两
个点的坐标值，其中包括一个测站点和一个照准点，因此需要四个坐标值｡
2.平面网的未知数
       当平面网在椭球面上平差时常常将点位的大地坐标(𝐵, 𝐿)作为未知数，而在
平面直角坐标时也将点位的平面直角坐标(𝑥 , 𝑦)作为未知数。以上二者当点在椭
球的不同位置时，有不同的换算关系 [23]，因此可以说在本质上二者的平差没有
区别，但平面上坐标与观测量(方向值,边长､方位角)的函数关系比椭球面上要简
单，在平面上的运算要比在椭球上减少一定的工作量，因此在实际平差中人们往
往选择在平面上平差｡[24]
       平面网中需要用点位坐标来表示各种不同的观测值，因此观测值的误差方程
均为非线性方程，平差中必须引入坐标的近似值，这个近似值直接用点位在地图
上的大地坐标转换为平面坐标来代替 [25]，并且还需要点与点之间的距离的近似
值，这个近似值通过百度地图的测距功能也可以实现。下面简单介绍不同观测值
的误差方程的列立方法。本节讨论间接平差函数模型的建立方法，即误差方程的
组成。这里给出三种不同模型的误差方程，分别是方向值、角度和边长。

4 网页端控制网优化
4 Web programming and implementation
4.1 程序开发目标与原则（Program development objectives and
principles）
  本文拟开发的利用在线地图的控制网优化设计程序，根据用户使用在线地图
界面选点，选择连线形成控制网，通过调用百度地图 API 得到点的经纬度，并
在前端程序中计算出线的方位角，线的实际距离和两线之间的夹角，程序获取点、
线、角和网的拓扑关系并以文本形式传出。传出的点位经纬度信息批量传入平差
软件中可以直接获取点位的高斯投影坐标，而点、线、角之间的拓扑关系传入到
矩阵运算程序中，根据用户选择测边网、测角网或是边角网，进行精度估算所相
关的运算。若不满足要求则需要用户在地图上增加或删除地图信息，从而获取新
的点位信息和拓扑关系。从程序本身来说，需要满足的原则有高效性、稳定性、
程序友好性等。

4.2 网页程序设计主要技术与原理（Main technology and principle
of web programming）
  网页程序的编写主要由三部分组成：HTML、CSS、JavaScript，它们分别表
示结构层、表示层和行为层。
  HTML 是超文本标记语言，它的作用是将代码命令给浏览器，让浏览器按照
代码运行，HTML 不像 C 和 C++在编写时有严格的要求，它在编写时没有严格
的大小写要求，即使标签没有结束也不会改变组织中的内容。它的编写没有逻辑
可言，主要是通过标签将每一个命令“打包”[30]。
  CSS，即层叠样式表，它作用是进行网页排版，通常网页中要添加很多内容，
不仅是网页中需要向用户提供的内容，还有用户与程序进行交互的窗口。一般来
说，越是著名的网页，越讲究界面的整洁性和用户的体验感[31]。
  JavaScript 是用来开发网络页面的脚本语言，它包括三部分内容：ECMAscript、
BOM、DOM,分别代表语法语句、浏览器对象、操作文档中的内容。JS 是弱类型
语言，它严格要求大小写，并且 JavaScript 的命名规则按照 Java 的标识符制定。
它有着很强的逻辑性，可以使静态的网页与用户实现交互，比如生成表单、输入
文本、制造动画等等[32]。

· 当 B 点相对于 A 点在一条 X 轴，且 B 点相对于 A 点在 Y 轴正半轴时，

𝐴𝑧𝑖𝑚𝑢𝑡ℎ = 0
· 当 B 点相对于 A 点在一条 X 轴，且 B 点相对于 A 点在 Y 轴负半轴时，
𝐴𝑧𝑖𝑚𝑢𝑡ℎ = 180
· 当 B 点相对于 A 点在一条 Y 轴，且 B 点相对于 A 点在 X 轴正半轴时，
𝐴𝑧𝑖𝑚𝑢𝑡ℎ = 90
· 当 B 点相对于 A 点在一条 Y 轴，且 B 点相对于 A 点在 X 轴正半轴时，
𝐴𝑧𝑖𝑚𝑢𝑡ℎ = 270
     以上过程中的全部运算都是把地球看做一个标准的球体，而实际上地球是一
个不规则的椭球体，因此以上过程存在一定误差。但由于在地图选取的控制网规
模较小，所以点与点之间的距离不会太大，另外地球的偏心率很小，所以整个计
算过程的偏差可以忽略不计[35]。
     在以上的原理基础之上，即可在程序中实现方位角测量的功能，实现代码如
下：
function getAzimuth(lng_a, lat_a, lng_b, lat_b) {
     a = (90 - lat_b) * Math.PI / 180;
     b = (90 - lat_a) * Math.PI / 180;
     AOC_BOC = (lng_b - lng_a) * Math.PI / 180;
     cosc = Math.cos(a) * Math.cos(b) + Math.sin(a) * Math.sin(b) * Math.cos(AOC_BOC);
     sinc = Math.sqrt(1 - cosc * cosc);
     sinA = Math.sin(a) * Math.sin(AOC_BOC) / sinc;
     A = Math.asin(sinA) * 180 / Math.PI;
     var res = 0;
     if (lng_b > lng_a && lat_b > lat_a) res = A;
     else if (lng_b > lng_a && lat_b < lat_a) res = 180 - A;
     else if (lng_b < lng_a && lat_b < lat_a) res = 180 - A;
     else if (lng_b < lng_a && lat_b > lat_a) res = 360 + A;
     else if (lng_b > lng_a && lat_b == lat_a) res = 90;
     else if (lng_b < lng_a && lat_b == lat_a) res = 270;
     else if (lng_b == lng_a && lat_b > lat_a) res = 0;
     else if (lng_b == lng_a && lat_b < lat_a) res = 180;
              return res;
    }

4.2.2.3 角度测量

   角度计算的基础是方位角的计算，有了方位角的计算角度只需要在其基础上
作差就可以求得，但是在计算方位角的过程中引入了当前点和目标点的概念，而

条边，它们各自的起始点之间的关系，并对其进行调整。下面是根据点位情况不
同计算角度的原理，设 1 号边为角的起边，2 号边为角的终边。

· 当 1 号边的终点是 2 号边的终点时，𝐴𝑛𝑔𝑒𝑙 = 𝐴𝑧𝑖𝑚𝑢𝑡ℎ(2) − 𝐴𝑧𝑖𝑚𝑢𝑡ℎ(1)
· 当 1 号边的起点是 2 号边的终点时，
                    𝐴𝑛𝑔𝑒𝑙 = 𝐴𝑧𝑖𝑚𝑢𝑡ℎ(2) − 𝐴𝑧𝑖𝑚𝑢𝑡ℎ(1) − 180

来计算系数矩阵中的元素，元素的计算方法都与点与点的 X 轴坐标之差、Y 轴
坐标误差和两点的距离相关，本节以测角网为例，结合矩阵运算程序实现的代码
介绍系数矩阵以及协因数矩阵的计算方法。
  ①确定系数矩阵的行数和列数。要想确定系数矩阵，则需要了解误差方程的
列立，根据第三章的介绍可以确定，系数矩阵的行数是由观测值的个数确定的，
列数是由未知数的个数确定的，为了方便计算可以先把系数矩阵设为一个所有元
素为零的矩阵，然后再按照观测角和角所涉及到的点计算出相应系数，在系数矩
阵中找到它的位置并添加进去。
  ②传入矩阵运算所需要的信息。所需要的信息包括所有点的高斯投影坐标，
以及用点的编号来表示的角度的信息，一个角度的表示需要三个点，传入矩阵时
需要把位于角的顶点的点的编号放在三个点的编号的中间，定义一个矩阵 JKH，
它的行数由角的个数决定，列数是三，这样就把所有角都存了进来。
  ③矩阵计算流程。定义三个变量，由这三个变量来循环遍历所有构成角的点，
循环遍历所有角完成后，就确定了在系数矩阵中不为零的值的位置。接着进行矩
阵元素的计算，计算方法根据点位的已知未知不同情况也有所变化，这里考虑的

6 总结与展望
6 Summary and Prospect
6.1 总结（Summary）
   本文通过研究百度在线地图的发展历程和现状，开发了一款网页端软件，做
的主要工作如下：
  一、实现了调用百度地图 API，为使对其能够满足控制网设计功能进行研究
开发，能够实现输入多个不同类型地图覆盖物，并获取
  二、实现了在百度在线地手动图选点构网并获取点位坐标，网页端软件操作
简单不需安装下载即可在网页端使用，整个网页操作简单易懂，控制网构建效率
高。并且能够同时构建控制网点、线、角、网之间的拓扑关系，更加直观的展示
构建的控制网，并在动态表格中即可进行删改。
  三、实现了在网页端的控制网精度估算，以间接平差原理为基础，可按照所
选的控制网中的元素进行精度估算的相关运算，以此来帮助用户判断控制网精度
是否满足要求。整个运算过程效率较高并且健壮性较好，即使控制网规模较大，
精度估算结果也很快能够在网页中展现。若出现控制网精度不满足要求情况，程
序可通过在原有控制网基础上人为增加或删除控制点、观测边的方法来补充控制
网以此来提高控制网精度。

6.2 展望（Prospect）
  整个网页虽然能够实现最基本的构建控制网和精度估算工作，但依旧在功能
和设计上有一些能够改进的地方，对整个程序设计的未来展望如下：
   一、整个程序在百度地图 API 的基础上实现，选用的是百度地图开放平台的
JavaScript API GL 和 JavaScript API v3.0 两个版本，以上两版本均未提供三维地
图，因此只能仅仅依靠点位的经纬度坐标信息转换位空间直角坐标系进行平差运
算，这也就意味着控制网精度估算的精度会受到影响。另外，在坐标换算方面，
百度地图是在 WGS84 坐标系上进行加密后得到的 BD09 坐标，而百度地图开放
平台未提供由 BD09 坐标反算 WGS84 坐标的方法，而本设计只考虑了小范围的
建网和运算，因此将 BD09 坐标当做 WGS84 坐标直接进行坐标转换，若是有大
面积布设控制网的需求，设计计算获取的控制网精度的误差会进一步增大。另外，
二维坐标的局限性还体现在不能解决两点之间的通视问题，若程序能在现有基础
上考虑到通视问题，控制网的构建就能够以自动+手动的方式实现，以此提高整
个程序的便捷性和高效性。另外我国通用坐标系主要是北京 54、西安 80 和国
家 2000。而软件中控制点坐标输入与输出均是 WGS84 坐标系，故软件还应需
添加坐标系转换功能，实现 WGS84 坐标系与我国通用坐标系相互转换。
