# Differing-content criss-cross bases: explicit whole-unit resolution

This stage adds one bounded capability: scenarios with differing-content best common ancestors can be merged through explicit whole-topology and/or whole-GNSS choices. If both tips agree on an affected unit, their converged content is accepted automatically. Units whose bases are equivalent retain the existing three-way behavior, including stable-ID field merges and conservative topology restrictions.

The sorted first base remains the legacy representative only. No differing unit is compared against that representative to infer a one-sided edit, and no virtual ancestor is synthesized. Preview reports `differing_base_units`; the browser explains that the choice retains an entire target/source unit. All best-base versions remain part of the transactional stale-preview check. Base IDs, guarded versions, dual parents and explicit resolutions remain persisted in scenario metadata.

Choosing an entire topology preserves that branch's authored points, lines, angles, selections, list order and allocator state; derived geometry is refreshed by the existing save/open path. This does not add automatic reconciliation of competing ancestor edits or relax the existing structural merge restrictions. Accepted v0.8 is unchanged; this is not production validation.
